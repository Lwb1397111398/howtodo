# 2026-10-22

## 适配旧版 Office 格式（.doc / .xls / .ppt）+ RTF / ODF / 网页另存

起因：用户反馈「不支持 doc 等 word 格式」。排查发现 `FileKinds` 把 `.doc/.xls/.ppt` 映射到
`SourceKind.OTHER`，`IngestPipeline` 走到 else 直接抛「暂不支持该格式」——只有 docx/xlsx/pptx 能进。

### 新增（全部零依赖，未引入 POI）

- `ingest/CfbReader.kt`：OLE2/CFB 只读解析器（FAT/MiniFAT/目录/流），按需 seek，单流上限 64MB；
  额外从 `\x05SummaryInformation` 读 PID_CODEPAGE，解决老 Word「压缩片段」按代码页存字节的问题。
- `ingest/LegacyOffice.kt`：
  - `.doc`：FIB → 片段表 CLX（Prc 跳过 / Pcdt 解析），压缩片段按代码页解码，未压缩走 UTF-16LE；
    Word 6/95 或片段表缺失时按 fcMin..fcMac 兜底，并靠字节分布判断是否 UTF-16；
    域代码 0x13/0x14/0x15 状态机丢弃指令保留结果，0x0D/0x07 转段落与制表符。
  - `.xls`：BIFF8 记录流；SST 支持 CONTINUE 续记录（续记录首字节是新的编码标志，不处理会整体错位）；
    LABELSST/NUMBER/RK/MULRK/FORMULA+STRING/LABEL；按 BOUNDSHEET 的 lbPlyPos 对齐 BOF 归属工作表。
  - `.ppt`：记录树递归，Slide 容器 0x03EE 分页，TextCharsAtom 0x0FA0 / TextBytesAtom 0x0FA8；
    结构异常时顺序扫原子的兜底。
- `ingest/RtfReader.kt`：`\ansicpg` 定编码，连续 `\'hh` 攒字节再解码（中文必须成对），`\uN` + `\ucN`，
  `\*` 与 fonttbl/pict 等目标组跳过。
- `ingest/DocumentExtract.kt`：统一入口，**先看魔数再看扩展名**：zip→docx/xlsx/pptx/ODF，
  OLE→doc/xls/ppt（含 EncryptedPackage 密码提示），`{\rtf`→RTF，HTML/UTF-16 BOM/纯文本兜底；
  `OfficeExtractors.odf()` 处理 odt/ods/odp。

### 改动

- `FileKinds`：doc/docx/docm/dot/rtf/odt/wps → DOCX 族；xls/xlsx/xlsm/xlt/ods/et → XLSX 族；
  ppt/pptx/pptm/pot/odp/dps → PPTX 族；补 msword/ms-excel/ms-powerpoint/rtf/opendocument 的 MIME 判断；
  `needsVision` 改回只认 IMAGE/PDF。
- `IngestPipeline`：非图片/PDF 一律走 `DocumentExtract`，进度文案按扩展名（旧库里的 OTHER 失败记录重试即可恢复）。
- UI：导入面板文案标注支持旧版；材料行的 `kind` 改成按扩展名说人话（不再直接显示 "DOCX"）。
- Manifest：补 rtf / opendocument 的 VIEW intent-filter。
- 版本：versionCode 2 / versionName 0.1.1（覆盖安装必须升 versionCode）。

### 验证

- 49 → 50 个单元测试全绿（新增 `LegacyOfficeTest` 7 个：Word 清洗、ANSI 解码、RTF、PPT 记录树、
  纯文本/RTF/HTML/UTF-16 嗅探、真实样本冒烟）。
- 真实样本对照（`HOWTODO_SAMPLE_DIR` 冒烟测试）：判决书 `.doc` 6435~10660 字、
  论文 `.doc`(cp936) 20461 字、`.xls` 学习计划 1106 字，均无乱码。
- `dist/工作如何做-v0.1.1-release.apk` 1.7MB，V2 签名证书 SHA-256 `6782cf3a...8157`（同 v0.1.0）。
