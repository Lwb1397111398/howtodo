# 检索增强模块总览

> 对应代码目录：`app/src/main/java/com/howtodo/rag/`

## 模块职责

材料问答（知识问答页与聊天页共用）：把用户问题检索成本地材料片段，装进预算内的上下文让 LLM 回答，并对回答做引用校验——**没有依据就说没有，杜绝编造截止时间**。

## 运作流程（按数据流动顺序）

### 1. 检索（rag/Retriever.kt + rag/Bigram.kt）

`Retriever.search(question, projectId, crossProject, limit)`：

- 关键词来自两路：`AiRouter` 调快速模型按 `Prompts.KEYWORD_SYSTEM` 改写问题（输出 2~6 个实义词 JSON，失败退化为本地分词）；命中片段表 `chunk`（按工作过滤或跨工作），用 `Bigram.encode()` 的 bigram 倒排（`chunk_fts` FTS5 表，机型不支持时降级 SQL LIKE）打分排序，取前 48 条。
- 命中的来源信息**批量**回表（`db.sourceDao().byIds` 一次取齐，原逐条 `byId` 是 N+1），关键词归一化也每个只算一次；带 chunk 正文、页码、字符区间。

### 2. 装上下文（Answerer.buildContext）

片段带 `[S1] [S2]` 编号，按 `TokenBudget.usable()` 预算贪心装包；单块超预算用 `TokenBudget.truncate` 压回（2026-10-27 起），保证 prompt 不爆模型上下文。同时生成引用清单 JSON（label/chunkId/sourceId/pageNo/quote/charStart/charEnd），回答里的 `[S3]` 靠它跳转原文。

### 3. 生成与校验（Answerer.answer）

- 系统提示词 `Prompts.CHAT_SYSTEM`：结论先行、事实句必须带 `[Sn]` 编号、没依据就明说。
- 消息组装：系统提示 + 最近最多 8 条历史（各截 2000 字）+ 本题 user prompt；经 `AiRouter.chatWith()` 走**单例 HTTP 客户端**（角色链 CHAT→REASONING→FAST）。
- 引用校验 `hasValidCitation()`：回答里所有 `[Sn]` 都必须是真实存在的编号；不合格就带着更强硬的提示重答一次，仍不合格则在回答尾部追加「未能在材料中找到明确出处」的警示，`grounded=false`。
- 检索零命中直接返回固定话术（换关键词/先导入材料/问对接人），不浪费一次模型调用。

## 入口文件清单

- `rag/Answerer.kt`：问答编排与引用校验
- `rag/Retriever.kt`：本地检索与打分
- `rag/Bigram.kt`：bigram 编码（也是 ingest 建索引用的同一套编码）

## 对外接口 / 被谁调用

- `Answerer.answer(question, projectId, crossProject, history)`：`ui/chat/ChatScreen`、`ui/knowledge/KnowledgeScreen`。
- `Retriever.search()`：材料库页的搜索框（`ui/materials/MaterialsScreen`）也直接用。
- `Answerer.Answer.citationsJson`：预览页按 chunkId/charStart 定位原文。

## 依赖的上游模块

`data`（chunk/source/knowledge/task 表）、`ai`（AiRouter、TokenBudget、Prompts、LlmClient）、`ingest`（建索引时的 Bigram 编码，两边必须一致）。

## 关键数据结构

- `Retriever.Hit`：chunk + sourceId + sourceName + 得分。
- `Answerer.Answer`：text / citationsJson / hitCount / model / promptTokens / completionTokens / grounded。
- 引用 JSON 数组：`[{label, chunkId, sourceId, sourceName, pageNo?, quote, charStart, charEnd}]`。

## 已知坑与约束

1. **Bigram 编码两处共用**：`ingest` 建索引与 `rag` 查询必须用同一版 `Bigram.encode()`，改一边检索就全哑。
2. **FTS5 机型差异**：`FtsStore.mode` 降级 LIKE 后精度下降但功能可用（见数据层总览）。
3. **引用编号必须真实存在**：模型编造 `[S9]` 会被校验拦下触发重答；重答仍失败就明示「无出处」，不静默放过。
4. **检索打分是纯本地启发式**：无向量模型参与，长问题与口语化提问依赖关键词改写那一步的质量。
