# 界面模块总览

> 对应代码目录：`app/src/main/java/com/howtodo/ui/`（Compose 界面层）

## 模块职责

用 Jetpack Compose 把本地数据渲染成 5 个主标签页 + 若干详情页，并把用户操作（导入、勾选分析、确认变更、材料重解析/删除）转成对 `AppContainer` 里各 Repo 的调用。

## 运作流程

### 路由与骨架

`ui/nav/AppNav.kt` 用 `NavHost` 定义全部路由：

| 路由 | 界面 | 说明 |
| --- | --- | --- |
| `today` | `ui/today/TodayScreen.kt` | 今日：待办、逾期、待确认变更、材料/聊天入口 |
| `projects` | `ui/projects/ProjectsScreen.kt` | 工作列表 |
| `materials` | `ui/materials/MaterialsScreen.kt` | 材料库（全部材料 + 全文检索） |
| `knowledge` | `ui/knowledge/KnowledgeScreen.kt` | 知识条目 |
| `settings` | `ui/settings/SettingsScreen.kt` | 设置（含检查更新、供应商入口） |
| `project/{projectId}` | `ui/project/ProjectScreen.kt` | 工作详情：任务 / 材料 / 变更 三个页签 |
| `proposal/{proposalId}` | `ui/project/ProposalScreen.kt` | 待确认变更逐条审阅 |
| `preview/{sourceId}?chunkStart=` | `ui/materials/PreviewScreen.kt` | 材料预览：图片/PDF 原件或正文分块 |
| `chat?projectId=` | `ui/chat/ChatScreen.kt` | 与材料对话 |
| `provider/{providerId}` | `ui/settings/ProviderScreen.kt` | 供应商与模型配置 |

底部导航只在 5 个主标签页显示；进入详情页后靠左上角返回。

### 数据怎么进界面

界面不自己查数据库，统一 `LocalContext.current.container()` 拿单例，再订 Repo 的 Flow：

- 材料库：`c.sourceRepo.observeAll()` → `SourceWithProject` 列表；搜索框输入 ≥2 字时延时 350ms 调 `c.retriever.search()` 做全文检索。
- 工作页：`c.taskRepo.observeByProject()`、`c.sourceRepo.observeByProject()`、`c.proposalRepo.observeByProject()` 三路 Flow；材料解析状态一变，列表标签自动从「解析中」翻成「已解析」或「解析失败」。
- 预览页：一次性读 `sourceRepo.byId()` + `chunkDao.bySource()`，图片/PDF 另用 `PdfIngest.renderOne()` 渲染首页。

### 材料相关的操作闭环（本次补齐）

1. **导入**：工作页右下角 FAB → `ImportSheet` → 相册 / 文件 / 拍照 / 粘贴文字；分享入口走 `ShareActivity`。
2. **归入工作**：材料库行内「未归类 · 归入工作」→ `AssignDialog` → `SourceRepo.setProject()` + `ProjectRepo.touch()`。
3. **重新解析**：材料库行、工作页材料行、预览页右上角「⋮」→ `ImportManager.reparse()`；失败行还额外显示错误原因与「重试解析」文字按钮。
4. **删除**：同一批入口 → `ConfirmDialog`（红色危险按钮）→ `SourceRepo.delete()`；预览页删除成功后自动返回上一页。
5. **AI 分析**：工作页勾选材料 → `ExtractionService.analyze()`，进度显示在不可取消的「请稍候」弹窗里，成功后跳到提案页。

### 状态与反馈

- 长任务用 `busy: String?` + 不可取消的 `AlertDialog` 展示，文案由解析/分析回调实时更新。
- 错误用 `error: String?` + 「出错了」弹窗，确认后清空。
- 列表状态（解析中/失败/已分析）直接读数据库字段，不做本地副本，避免与后台任务不同步。

- `ui/project/ProjectScreen.kt`、`ui/project/ProposalScreen.kt`

## 对外接口 / 被谁调用

- `AppNav(startProjectId, onStartConsumed)`：`MainActivity` 调用；从提醒通知进来时直接落到对应工作。
- 各 Screen 的 `onOpenPreview` / `onOpenProject` / `onBack` 回调：由 `AppNav` 注入导航动作。
- 界面层向下只依赖 `AppContainer` 暴露的 Repo / Manager，不直接持有数据库连接。

## 依赖的上游模块

`data`（Repo 与 Flow）、`ingest`（`ImportManager` 导入与重解析）、`ai`（`ExtractionService` 分析）、`rag`（`Retriever` 材料搜索）、`update`（设置页检查更新）、`util`（格式化、容器扩展）。

## 关键数据结构

- `SourceWithProject`、`TaskWithProject`：列表渲染的基本单位。
- `busy` / `error` / `selected` / `deleteTarget`：各屏的局部 UI 状态（`remember { mutableStateOf(...) }`），不跨屏共享。
- `Routes`：路由常量与参数拼装函数。

## 已知坑与约束

1. **Compose 状态随导航重建**：详情页状态不持久，离开再回来会重新读库；这是有意为之，避免展示过期数据。
2. **列表点击与行内按钮嵌套**：`Surface(clickable)` 里放 `IconButton` / `TextButton` 时子级会吃掉点击，不要在外层再包一层 `clickable` 处理同一动作。
3. **长任务弹窗不可取消**：解析/分析中按返回键无效，必须等结束；这是为了防止用户中途离开导致状态错乱。
4. **解析失败的错误文案来自后端**：界面只负责原样展示 `source.error`（最多两行），新增失败原因时在后端写中文，不要在前端映射。
5. **搜索与列表是两种数据源**：搜索框 ≥2 字时列表换成检索命中，清空后回到全量材料；改检索逻辑时别只改其中一支。
6. **预览页图片/PDF 与正文互斥**：图片、PDF 只渲染原件，不展示 chunk 文本；文档类只展示 chunk。
