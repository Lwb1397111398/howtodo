# 提醒通知模块总览

> 对应代码目录：`app/src/main/java/com/howtodo/notify/`（配合 `data/repo/ReminderRepo.kt`、`TaskRepo.kt` 的状态联动与 `ui/settings` 的开关入口）

## 模块职责

让截止日期真正「叫得到人」：按任务的截止日生成 D-3 / D-1 / 当天三档提醒，用精确闹钟在指定时刻弹出通知；外加每天早上的事项汇总（每日早报）；开机、改时间、覆盖安装后全量重建闹钟。

## 运作流程（按数据流动顺序）

### 1. 提醒怎么生成（data/repo/ReminderRepo.kt）

任务处于 TODO 且填了截止时间时，`ReminderRepo.rescheduleTask(task)` 按截止日生成最多三档 `ReminderEntity`（受设置 `remind.d3` / `remind.d1` / `remind.d0` 开关控制，缺省全开）：

- **D3**：截止日前 3 天 09:00；
- **D1**：前 1 天 09:00；
- **D0**：有具体时刻的提前 2 小时，否则当天 09:00。

防重复靠两层：`dedupeKey = taskId|kind|yyyy-MM-dd` 上有**数据库唯一索引**（v2 迁移建的，`OnConflictStrategy.IGNORE` 插入天然幂等）；闹钟编号 `requestCode` 直接用行 id（旧版是哈希、会碰撞互覆盖，已由 v1→v2 迁移统一）。

生成时机：`TaskRepo.toggleDone` 把误完成的任务重新打开时（过期档位自动跳过）、设置页三档开关变化时（`rescheduleAll` 全量重排）、通知「稍后再提醒」补建时。

### 2. 闹钟注册（notify/AlarmScheduler.kt）

`AlarmScheduler.schedule(r)` 把每条 SCHEDULED 提醒注册成 `AlarmManager` 闹钟：有「精确闹钟」权限走 `setExactAndAllowWhileIdle`（最准），没有则退 `setAndAllowWhileIdle`（可能延后几分钟）；`PendingIntent` 指向 `ReminderReceiver`，requestCode 用提醒行 id。

### 3. 闹钟到点（notify/Receivers.kt → Notifications.kt）

`ReminderReceiver` 收到闹钟后查提醒与任务，按状态分流：

- 任务已 **DONE / CANCELLED** → 不弹通知，提醒记「已提醒」收尾（已取消任务不再骚扰是 2026-10-27 修的）；
- 通知**权限未授予** → 弹不出去，提醒记「错过」（MISSED）而不是假装送达，设置页的权限行会显示「未允许（提醒不会弹出）」；
- 正常 → `Notifications.showTaskReminder()` 弹高优先级通知（标题按档位：还有 3 天 / 明天截止 / 今天截止 / 已逾期），带「标记完成」「1 小时后再提醒」两个按钮动作，提醒记「已提醒」。

通知按钮的 PendingIntent 编号用 `taskId.hashCode()*2 + 动作序号` 全宽映射（旧版压进 4096 个桶会点错任务，已修）。

### 4. 通知动作回流

- **标记完成** → `TaskRepo.setStatus(DONE)`（连带把该任务全部提醒翻成 CANCELLED）；
- **稍后再提醒** → 提醒的 triggerAt 改为 1 小时后并重新注册闹钟；找不到原提醒行时按任务补排。

### 5. 每日早报（notify/DailyDigestWorker.kt）

WorkManager 按设置 `digest.hour/minute`（缺省 08:00）每天跑一次：汇总逾期 / 今日 / 三天内数量与前几条标题，经 `Notifications.showDigest()` 发一条汇总通知；三项全空不发。`App.onCreate` 里 `ensureScheduled()` 保证计划存在。

### 6. 重建（notify/Receivers.kt 的 BootReceiver）

系统重启会清掉所有 `AlarmManager` 闹钟。`BootReceiver` 监听 `BOOT_COMPLETED` / `TIME_CHANGED` / `TIMEZONE_CHANGED` / `MY_PACKAGE_REPLACED` / `DATE_CHANGED`，触发 `AlarmScheduler.rescheduleAll()` 按数据库全量重注册；错过超过 1 分钟的一次性提醒直接记「已提醒」跳过，避免开机瞬间连环弹窗。

## 入口文件清单

- `notify/AlarmScheduler.kt`：闹钟注册与全量重建
- `notify/Notifications.kt`：三个通知渠道（任务提醒/每日早报/解析进度）与通知构建
- `notify/Receivers.kt`：`ReminderReceiver`（闹钟与通知动作）、`BootReceiver`（重建）
- `notify/DailyDigestWorker.kt`：每日早报 Worker
- 配合：`data/repo/ReminderRepo.kt`（提醒行生成与状态）、`data/repo/TaskRepo.kt`（状态联动）、`ui/settings/SettingsScreen.kt`（三档开关、早报时间、权限入口）

## 对外接口 / 被谁调用

- `App.onCreate`：`Notifications.ensureChannels()`、`DailyDigestWorker.ensureScheduled()`、`alarmScheduler.rescheduleAll()`。
- `TaskRepo`：完成/取消任务时调 `reminderDao.cancelByTask`；重开任务时调 `reminderRepo.rescheduleTask + alarmScheduler.schedule`。
- `MainActivity`：通知点击带 `taskId` extra 落到对应工作。
- `IngestPipeline` 解析完成 → `Notifications.showParseDone()`（解析进度渠道）。

## 依赖的上游模块

`data`（reminder / task / app_setting 表与 ReminderRepo）、`di/AppContainer`（appScope、各单例）。TaskRepo 依赖本模块的 AlarmScheduler（构成 data ↔ notify 的温和耦合，无循环）。

## 关键数据结构

- `ReminderEntity`：`id / taskId / kind(D3|D1|D0) / triggerAt / state / requestCode(=行id) / dedupeKey(唯一索引)`。
- `ReminderState`：SCHEDULED → FIRED / CANCELLED / MISSED。
- SharedPreferences `update_prefs` 无关；早报设置在 `app_setting` 表（`digest.enabled/hour/minute`、`remind.d3/d1/d0`）。

## 已知坑与约束

1. **国产 ROM 自启动限制**：小米/华为等还需系统设置里允许自启动，否则重启后 BootReceiver 收不到（设置页有文案提示）。
2. **权限补授不补发**：通知权限被拒期间的提醒记 MISSED，授予权限后不会自动补发历史提醒，要等下一次重排或新提醒。
3. **闹钟不做主动 cancel**：完成/取消任务只翻数据库状态，已注册的闹钟到点由 Receiver 状态检查兜底跳过（与原设计一致，省去逐条 cancel 的复杂度）。
4. ** requestCode 历史数据**：v1 时代的哈希 requestCode 已由 MIGRATION_1_2 统一改写为行 id；新旧行不会混用。
5. **通知 ID 的哈希碰撞**：`notificationId = taskId*31 + kind` 理论上可碰撞（概率极低），表现是旧通知被新通知替换，可接受。
